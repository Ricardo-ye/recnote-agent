# RecNote Agent｜面试项目介绍

> 本文区分已实现能力与后续验证计划；不将模拟数据、离线规则或待做的用户研究表述为线上成果。

## 1. 项目整体介绍

**背景与目标。** 会议转写、访谈和临时记录通常无结构、难检索且容易在整理中丢失上下文。RecNote 将原始文字处理为可检索、可溯源、可回滚的结构化笔记，并把不确定内容交给用户确认。

**主要功能。**

- 语义切片、分类、摘要、槽位和标签提取；
- 相似笔记检测、合并建议、人工确认队列；
- 笔记版本、字段级 diff、回滚与原文溯源；
- BM25 检索、分类/标签筛选，以及 JSON 导入导出；
- 默认离线规则引擎；可选 OpenAI 兼容 LLM 对待确认建议做分类和提炼增强；
- 受限工具契约和三层记忆数据模型：会话、任务、长期偏好。

**技术栈。** 原生 HTML/CSS/JavaScript、localStorage、TF-IDF、余弦相似度、BM25 变体；可选 `fetch` 调用 OpenAI 兼容网关。

**架构流程。**

```text
素材 → 语义切片 → 本地多信号分类 → 提炼 → 去重
     → 高置信自动入库 / 低置信进入确认队列
                              ↓（可选）
                         LLM 分类与提炼增强
                              ↓
                           人工接受、改判或丢弃
```

## 2. 我的职责与关键产出

- 设计从素材、片段、建议到笔记版本的可追溯数据模型；
- 实现固定且可离线运行的五步处理管线、置信度降级和去重合并机制；
- 将所有正式写入约束在 `Store` 方法内，确保版本链不被跳过；
- 新增可选 LLM 增强层：超时、响应 JSON 校验、分类白名单、失败隔离和本地回退；
- 定义只读/草稿型工具契约，禁止模型直接写入正式笔记；
- 新增可过期、可删除、可按范围召回的记忆数据模型。

## 3. 亮点与难点

| 亮点/挑战 | 解决方式 |
|---|---|
| 不能让自动整理破坏原文或覆盖人工判断 | 原文、片段、建议、笔记和版本分层保存；低置信和疑似重复强制进入确认队列。 |
| LLM 不稳定且静态前端不适合保存密钥 | 默认离线；请求有超时和结构校验；密钥只在浏览器会话中暂存，生产环境建议改为同源服务端代理。 |
| 防止“工具调用”变成不受控写入 | 工具仅允许分类、草稿、记忆检索；正式写入仍需用户确认。 |
| 记忆会过期、污染或泄露 | 区分会话/任务/长期范围，记录来源和 TTL，提供删除接口；长期记忆默认不由模型自动写入。 |

## 4. 优缺点与改进方向

| 维度 | 优势 | 当前不足 | 下一步 |
|---|---|---|---|
| 设计 | 人在环、溯源和回滚边界清晰 | LLM 增强目前只覆盖待确认项 | 增加服务端任务队列与审批 trace。 |
| 性能 | 本地规则无网络延迟，可离线 | 大量素材时浏览器内计算和 localStorage 容量有限 | 迁移 IndexedDB / 后端索引服务。 |
| 可维护性 | 纯前端、依赖少、数据可导出 | 目前没有后端鉴权和多租户模型 | 引入 API、用户隔离与端到端审计。 |
| 验证 | 可通过页面 E2E 验证核心交互 | 尚无真实用户可用性研究结论 | 完成 3–5 名真实用户任务测试，保存脱敏原始记录与迭代证据。 |

## 5. 3–5 分钟讲述要点

“我做的是 RecNote，一个把会议转写和访谈材料自动整理为可追溯知识库的工具。它解决的不是转写，而是整理后内容不可检索、自动化又不可信的问题。

系统先用离线的语义切片、TF-IDF 分类、抽取式摘要和相似度查重生成建议。我的关键设计是把不确定性产品化：低置信分类和疑似重复不直接写库，而是进入确认队列；所有人工修改也会产生版本，因此用户能看到来源、差异并回滚。

在此基础上，我把 LLM 做成可选增强而不是替换规则。调用只处理待确认项，响应必须通过 JSON、分类白名单和超时校验；失败时保持本地结果不阻断主流程。模型只能调用分类、草稿和记忆检索等受限工具，不能直接写入正式笔记，最终仍由人确认。

项目的优势是可解释、离线可运行和数据主权清晰。局限是目前是浏览器单机原型，没有多用户服务端和真实用户研究数据。下一步我会将网关和记忆迁到服务端，并用真实可用性测试验证整理效率和信任感是否提升。”
